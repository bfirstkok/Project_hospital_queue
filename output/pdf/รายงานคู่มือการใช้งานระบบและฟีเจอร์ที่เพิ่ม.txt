รายงานคู่มือการใช้งานระบบและฟีเจอร์ที่เพิ่ม
===========================================

ระบบจัดการคิวผู้ป่วยนอกและติดตามสัญญาณชีพ

ฉบับวันที่ 7 ตุลาคม 2569  |  สำหรับเจ้าหน้าที่และผู้ดูแลระบบ

วัตถุประสงค์และขอบเขต
=====================

คู่มือนี้อธิบายการใช้งานเว็บเจ้าหน้าที่ตามหน้าที่ ตั้งแต่ลงทะเบียนจนจบการรับบริการ และสรุปฟีเจอร์คู่มือในเว็บที่เพิ่มรอบนี้ ผู้ใช้ควรอ่านส่วนร่วมแล้วไปยังตำแหน่งของตนก่อนเริ่มงานจริง

ระบบเป็นต้นแบบสำหรับ OPD และการรับช่วงฉุกเฉิน ไม่ครอบคลุมการจัดเตียงหรือการดูแลผู้ป่วยนอนโรงพยาบาล ผล AI ใช้ช่วยการประเมิน โดยพยาบาลเป็นผู้ยืนยันระดับคัดกรองและแพทย์เป็นผู้วินิจฉัย

ภาพรวมการส่งต่องาน
==================

1. เวชระเบียนค้นหาและลงทะเบียนผู้ป่วย หรือเปิด Visit ใหม่สำหรับผู้ป่วยเดิม
2. ผู้ช่วยพยาบาลวัดและบันทึกสัญญาณชีพ ส่งผลไปให้พยาบาลยืนยัน
3. พยาบาลทบทวนผล AI และกฎความเสี่ยง ยืนยันระดับสุดท้าย และมอบหมายการเฝ้าระวังตามเงื่อนไข
4. เจ้าหน้าที่จัดคิวเรียกเข้าห้องตรวจ แพทย์บันทึกผลตรวจและแผนหลังตรวจ
5. ห้องยาดำเนินการตามใบสั่งยา การเงินตรวจสิทธิและรับชำระ แต่ละจุดมีสถานะและคิวของตน
6. เจ้าหน้าที่จัดคิวปิด Visit เมื่อขั้นตอนก่อนหน้าครบและผู้ป่วยออกจริง ผู้ป่วยจึงกลับมาใช้บริการครั้งใหม่ได้

กรณีฉุกเฉินหรือส่ง ER จะเข้าสู่รายการรับช่วงฉุกเฉินตามเงื่อนไขของระบบ ไม่เดินเส้นทาง OPD ปกติทั้งหมด และสถานะชำระเงินกับจ่ายยาแยกกัน

ฟีเจอร์คู่มือที่เพิ่มในรอบนี้
=============================

เราเพิ่มคู่มือในเว็บเพื่อให้ผู้ใช้รู้ว่าหน้าที่ของตนต้องเริ่มตรงไหนและส่งต่องานอย่างไร การเปลี่ยนแปลงรอบนี้เป็นส่วนอธิบายการใช้งาน ไม่เปลี่ยนกฎคิว การคำนวณบิล หรือผลคัดกรอง

1. ป๊อปอัปคู่มือหลังเข้าสู่ระบบ แสดงเนื้อหาตามหน้าที่ของบัญชี ครบ 9 ตำแหน่งและผู้ดูแลระบบสูงสุด ผู้ใช้เลือกอ่านหรือข้ามได้ก่อนเริ่มงาน
2. คู่มือทีละหัวข้อ มีสารบัญ ปุ่มหัวข้อก่อนหน้าและหัวข้อถัดไป ตัวบอกความคืบหน้า และปุ่มอ่านครบแล้วเพื่อปิดหน้าต่าง
3. เนื้อหาอธิบายวิธีเข้าหน้างาน ปุ่มที่ต้องใช้ ความหมายสถานะ จุดส่งต่อ และข้อควรตรวจ ก่อนเปลี่ยนสถานะผู้ป่วย
4. ลิงก์เปิดหน้าที่เกี่ยวข้องจากคู่มือ ใช้ชื่อเส้นทางของ Django และเลือกให้ตรงกับสิทธิ์ของตำแหน่ง ลิงก์ผู้ป่วยของฉันของพยาบาลเปิดแท็บผู้ป่วยโดยตรง
5. เมนูคู่มือการใช้งานในแถบซ้าย เปิดอ่านซ้ำได้เสมอ แม้ผู้ใช้จะเคยกดข้ามหรือเลือกไม่แสดงวันนี้
6. ตัวเลือกไม่แสดงอีกในวันนี้ จำแยกบัญชีและบทบาทในเบราว์เซอร์เดียวกันจนถึงวันถัดไป ตามวันปฏิทิน Asia/Bangkok ไม่ใช่ระยะเวลา 24 ชั่วโมงนับจากที่กด
7. ไม่รบกวนซ้ำทุกครั้งที่เปลี่ยนหน้า เมื่อเปิดคู่มือแล้วจะจำการแสดงในแท็บและการเข้าสู่ระบบครั้งเดิม หากไม่ได้ติ๊กซ่อนวันนี้ การเข้าสู่ระบบครั้งใหม่จะแสดงอีก
8. รองรับการสวมบทบาทของผู้ดูแล คู่มือจะเปลี่ยนตามบทบาทที่กำลังทดสอบ โดยไม่เพิ่มสิทธิ์ให้ผู้ใช้ทั่วไป
9. รองรับจอคอมและมือถือ ปิดด้วยปุ่มกากบาทหรือ Escape ได้ และแจ้งผู้ใช้เมื่อเบราว์เซอร์ไม่อนุญาตให้จำตัวเลือก

ฟีเจอร์ของระบบที่มีอยู่ก่อนรอบคู่มือ
====================================

ส่วนต่อไปนี้เป็นฟีเจอร์ของระบบปัจจุบันที่คู่มือนำมาอธิบายวิธีใช้ ไม่ใช่ฟีเจอร์ที่สร้างเพิ่มด้วยงานป๊อปอัปคู่มือรอบนี้

1. ห้องยาและการเงินมีคิวบริการแยกกัน เรียงตามเวลาที่เข้าสู่จุดบริการ และใช้หมายเลขคิวเดิมพร้อมลำดับของจุดบริการนั้น
2. เมื่อเรียกแล้วผู้ป่วยไม่มา สามารถข้ามคิวเพื่อเรียกรายถัดไป และส่งรายที่กลับมาเข้าคิวท้ายแถว โดยไม่ลบใบสั่งยาหรือบิลเดิม
3. จอคิวกลางแยก OPD ห้องยา และการเงิน จอสาธารณะไม่แสดงชื่อ HN หรือยอดชำระของผู้ป่วย
4. หน้าผู้ป่วยของเวชระเบียนมีภาพรวม Visit ล่าสุด แท็บสถานะ และยอดค้าง เพื่อช่วยตรวจว่าค้างขั้นตอนใด
5. ผู้ป่วยเดิมที่มียอดค้างสามารถเริ่ม Visit ใหม่กรณีเร่งด่วนตามสิทธิ์และเหตุผลที่กำหนด และโอนยอดค้างเข้าไปในบิลใหม่ บิลต้นทางเป็นโอนยอดแล้วเพื่อป้องกันรับชำระซ้ำ
6. แพทย์เลือกยาจากรายการค้นหาได้ รวมยารับประทานและยาทา ห้องยาและการเงินมีหน้ารายการกับรายละเอียดผู้ป่วยในหน้างานเดียวกัน

ตำแหน่งและเมนูหลัก
==================

เจ้าหน้าที่เวชระเบียน : ลงทะเบียน และ ผู้ป่วย
ผู้ช่วยพยาบาล : วัดค่า
พยาบาลวิชาชีพ : คัดกรอง ติดตาม และ ผู้ป่วยของฉัน
เจ้าหน้าที่จัดคิว : คิว และ ปิด Visit
แพทย์ : ห้องตรวจ
เจ้าหน้าที่ฉุกเฉิน : ฉุกเฉิน
เจ้าหน้าที่เครื่องมือแพทย์ : อุปกรณ์
เภสัชกร : ห้องยา
เจ้าหน้าที่การเงิน : การเงิน
ผู้ดูแลระบบสูงสุด : ภาพรวม บุคลากร เวร Admin และ รายงาน
วิธีใช้คู่มือในเว็บ
===================

1. เข้าสู่ระบบด้วยบัญชีของตน ตรวจชื่อและตำแหน่งในแถบเมนู ป๊อปอัปจะแสดงคู่มือของบทบาทที่ใช้งานอยู่
2. กดอ่านคู่มือเพื่อเปิดสารบัญ เลือกหัวข้อหรือกดหัวข้อถัดไปเพื่ออ่านทีละส่วน ปุ่มเปิดหน้างานจะปิดคู่มือแล้วพาไปหน้าที่เกี่ยวข้อง
3. หากต้องเริ่มงานทันที กดข้าม หรือปิดด้วยกากบาท/Escape ระบบจะไม่เด้งซ้ำเมื่อเปลี่ยนหน้าในแท็บและการเข้าสู่ระบบครั้งนั้น
4. ถ้าไม่ต้องการให้เด้งอีกในวันเดียวกัน ให้ติ๊กไม่แสดงอีกในวันนี้ก่อนอ่านหรือข้าม วันถัดไปเมื่อเปิดหน้าเว็บใหม่หรือเข้าสู่ระบบอีกครั้งจะแสดงได้ตามปกติ
5. เปิดอ่านซ้ำจากเมนูคู่มือการใช้งานด้านซ้ายได้ทุกเวลา หากต้องการกลับมาแสดงอัตโนมัติ ให้เปิดคู่มือ เอาติ๊กไม่แสดงอีกในวันนี้ออก แล้วปิดคู่มือ คู่มือจะแสดงอีกเมื่อเข้าสู่ระบบครั้งใหม่ ไม่เด้งซ้ำในครั้งเดิม

การเริ่มและจบงานที่ใช้ร่วมกันทุกตำแหน่ง
=======================================

1. ตรวจชื่อและหน้าที่ของตนที่แถบเมนู แล้วกด ‘เริ่มเวร’ เมื่อพร้อมทำงาน ดูวันและเวลาที่ได้รับมอบหมายในเมนู ‘เวร’
2. เมนู ‘สิทธิ์’ แสดงงานที่บัญชีนี้ทำได้ ส่วน ‘ตั้งค่า’ ใช้เปลี่ยนรหัสผ่านของตน หากไม่เห็นเมนูที่ต้องใช้ ให้แจ้งผู้ดูแลตรวจบทบาท
3. เมื่อจบงาน ให้กด ‘สิ้นสุดเวร’ และ ‘ออกจากระบบ’ โดยเฉพาะเครื่องที่ใช้ร่วมกัน การเปลี่ยนสถานะผู้ป่วยควรกดหลังดำเนินการจริงและตรวจข้อความผลลัพธ์ทุกครั้ง

การระบุตัวผู้ป่วยและการอ่านสถานะ
================================

HN คือเลขทะเบียนประจำตัวผู้ป่วย Visit คือการมารับบริการหนึ่งครั้ง คนเดิมอาจมีหลาย Visit ส่วนเลขคิวใช้ระบุตัวผู้ป่วยในคิวของการมาครั้งนั้น ก่อนบันทึกให้ตรวจชื่อ HN และ Visit ให้ตรงเสมอ

การตรวจเสร็จไม่เท่ากับชำระเงินแล้วหรือรับยาแล้ว แต่ละจุดต้องยืนยันงานของตนหลังดำเนินการจริง การปิด Visit ทำได้เมื่อเงื่อนไขก่อนหน้าครบและผู้ป่วยออกจากโรงพยาบาลจริง

สิทธิ์และข้อมูลส่วนบุคคล
========================

เมนูที่เห็นขึ้นกับสิทธิ์ของบทบาท ส่วนผู้ป่วยที่รับผิดชอบและการแจ้งเตือนขึ้นกับการมอบหมาย คู่มือไม่ปลดล็อกสิทธิ์เพิ่ม หากไม่เห็นเมนูที่ต้องทำ ให้ผู้ดูแลตรวจบัญชีและบทบาท หากติดปัญหาการรับเคส ให้ตรวจเวรและการมอบหมายด้วย ไม่ใช้บัญชีผู้ดูแลร่วมกันเพื่อข้ามสิทธิ์ และไม่เปิดข้อมูลผู้ป่วยบนจอคิวสาธารณะ

คู่มือเจ้าหน้าที่เวชระเบียน
===========================

ค้นหาหรือขึ้นทะเบียนผู้ป่วย เปิดการรับบริการครั้งใหม่ และตรวจผู้ป่วยที่ค้างขั้นตอนหรือมียอดค้าง

เมนูหลักที่ใช้  ลงทะเบียน และ ผู้ป่วย

ตรวจสถานะและค้นหาผู้ป่วยก่อนลงทะเบียน
=====================================

1. เปิดเมนู ‘ผู้ป่วย’ แถบ ‘ภาพรวมสถานะผู้ป่วย’ แสดง Visit ล่าสุดของแต่ละคน กดแท็บรอวัดค่า รอคัดกรอง รอเรียกคิว ห้องยา การเงิน หรือมียอดค้างเพื่อแยกรายการ
2. พิมพ์ HN ชื่อ เลขบัตรประชาชน หรือเบอร์โทร แล้วกด ‘ค้นหา’ ตรวจชื่อและ HN ก่อนเปิด ‘ประวัติ’ เพื่อดูการรับบริการและผู้ดำเนินการย้อนหลัง
3. แท็บสถานะหมายถึงขั้นตอนล่าสุด ส่วนยอดค้างเป็นภาระที่ยังต้องชำระ ผู้ป่วยหนึ่งคนอาจมีบิลเก่าค้างอยู่แม้ Visit ล่าสุดไปถึงขั้นตอนอื่นแล้ว

ลงทะเบียนใหม่หรือรับบริการผู้ป่วยเดิม
=====================================

1. เปิด ‘ลงทะเบียน’ ถ้าเคยมาแล้ว ให้เลือก ‘ค้นหาผู้ป่วยเดิม’ และเลือกคนที่ตรงกัน ระบบใช้ทะเบียน/HN เดิมและสร้าง Visit กับคิวสำหรับการมาครั้งใหม่
2. ถ้าเป็นผู้ป่วยใหม่ กรอกข้อมูลที่มีเครื่องหมาย * ให้ครบ ตรวจเบอร์โทร วันเกิด อาการสำคัญ โรคประจำตัว และประวัติแพ้ตามข้อมูลที่ได้รับ ก่อนยืนยันความยินยอม
3. กด ‘ยืนยันลงทะเบียน →’ หรือ ‘ยืนยันรับบริการครั้งใหม่ →’ แล้วตรวจข้อความสำเร็จ ผู้ป่วยจะเข้าสู่ขั้นตอนรอวัดสัญญาณชีพ หากระบบแจ้งว่ามี Visit ที่ยังไม่จบ ให้ตรวจขั้นตอนเดิมก่อนเปิดซ้ำ

ผู้ป่วยเดิมมียอดค้างและต้องรักษาเร่งด่วน
========================================

1. เมื่อเลือกผู้ป่วยเดิมแล้วพบ ‘มียอดค้างจาก Visit ก่อนหน้า’ ตรวจเลข Visit และยอดแต่ละบิล ปกติให้ดำเนินการบิลเดิมให้ครบก่อน
2. กรณีจำเป็นเร่งด่วน เลือก ‘เริ่ม Visit ใหม่กรณีเร่งด่วน และรวมยอดค้างทั้งหมดไว้ในบิลของ Visit ใหม่นี้’ พร้อมกรอกเหตุผลที่ข้ามขั้นตอนเดิม แล้วกดยืนยัน
3. ระบบย้ายยอดที่ผู้ป่วยต้องจ่ายไปแสดงแยกในบิลใหม่ บิลต้นทางเป็น ‘โอนยอดแล้ว’ จึงต้องให้การเงินรับชำระที่บิลใหม่ ตรวจประวัติเพื่อดูต้นทางและเหตุผลการโอน

แก้ข้อมูลและจัดการนัดติดตาม
===========================

1. เมื่อเปิดหน้า ‘แก้ไขข้อมูลผู้ป่วย’ ให้ตรวจชื่อและ HN ก่อนแก้ช่องที่ต้องการ แล้วกด ‘บันทึกการแก้ไข →’ การแก้ทะเบียนไม่สร้าง Visit หรือเลขคิวใหม่
2. ในประวัติผู้ป่วยส่วน ‘นัดติดตาม’ กรอกวันเวลาและหมายเหตุแล้วกด ‘เพิ่มนัด’ ตรวจรายการเดิมก่อนเพิ่ม และเปลี่ยนสถานะนัดตามผลที่เกิดขึ้นจริง
3. ใช้ประวัติ Visit และ Audit Log ตรวจว่าใครทำขั้นตอนไหนเมื่อไร แสดงข้อมูลส่วนบุคคลเฉพาะผู้มีหน้าที่เกี่ยวข้อง และไม่เปิดหน้าประวัติบนจอคิวกลาง

คู่มือผู้ช่วยพยาบาล
===================

วัดและบันทึกข้อมูลสุขภาพให้ถูกคน ส่งผลประเมินให้พยาบาลวิชาชีพยืนยันก่อนเข้าคิวตรวจ

เมนูหลักที่ใช้  วัดค่า

เลือกผู้ป่วยที่รอวัดค่า
=======================

1. เปิดเมนู ‘วัดค่า’ จะพบรายการ ‘รอวัดค่าสัญญาณชีพ’ ค้นหาด้วยชื่อ HN เลขบัตร หรือเบอร์โทร แล้วตรวจชื่อและเลขคิวรับข้อมูลให้ตรงกัน
2. ใช้เมนู ⋮ หลังชื่อเพื่อเลือก ‘ดูข้อมูลผู้ป่วย’ ตรวจอาการสำคัญและประวัติที่บันทึกไว้ แล้วกด ‘ประเมินสุขภาพ →’ ในแถวผู้ป่วยเพื่อเปิดแบบบันทึก

กรอกสัญญาณชีพและข้อมูลประกอบ
============================

1. กรอกอัตราหายใจ ชีพจร ความดันตัวบน/ตัวล่าง อุณหภูมิ และออกซิเจนในเลือดตามค่าที่วัดได้จริง ตรวจหน่วยและตำแหน่งช่องก่อนบันทึก
2. ถ้ายังไม่ได้วัดช่องใด ให้ใช้ช่อง ‘ยังไม่ได้วัด’ ของรายการนั้น กรอกอาการ ปัจจัยเสี่ยง กลุ่มพิเศษ และข้อมูลคัดกรองตามสิ่งที่ประเมินได้ภายใต้การกำกับของพยาบาล
3. กด ‘บันทึกไว้ก่อน’ เมื่อข้อมูลยังไม่ครบหรือยังไม่พร้อมส่ง ระบบเก็บฉบับร่างไว้ให้กลับมาตรวจทานต่อ

ส่งผลไปให้พยาบาลยืนยัน
======================

1. ตรวจข้อมูลครบแล้วกด ‘ประเมินและส่งไปรอยืนยัน’ ระบบประเมินข้อมูลด้วย AI และกฎตรวจความเสี่ยง แล้วส่งเคสเข้าสถานะรอพยาบาลยืนยัน
2. ผลประเมินล่าสุดเป็นข้อมูลช่วยตัดสินใจ พยาบาลวิชาชีพเป็นผู้ยืนยันระดับสุดท้าย บทบาทผู้ช่วยพยาบาลไม่ใช่ผู้กดรับรองสีหรือเรียกคิวห้องตรวจ
3. หากพยาบาลส่งกลับมาประเมินใหม่ ผู้ป่วยจะกลับมารายการวัดค่า เปิดเคสเดิมแก้ข้อมูลแล้วส่งไปรอยืนยันอีกครั้ง

ตรวจผลบันทึกและแก้ข้อมูลไม่ครบ
==============================

1. หากระบบแจ้งข้อผิดพลาด ให้ดูข้อความข้างช่องที่มีปัญหาและแก้ตามข้อมูลจริง เมื่อบันทึกสำเร็จแล้ว ตรวจว่ารายการย้ายออกจากรอวัดค่าตามขั้นตอนที่เลือก
2. ถ้ารายการไม่ตรงกับผู้ป่วย ให้ย้อนกลับเลือกคนใหม่ก่อนกรอก แจ้งพยาบาลเมื่อพบข้อมูลขัดกันหรือมีอาการเปลี่ยนระหว่างรอ แทนการปรับค่าที่วัดเพื่อให้ได้สีที่ต้องการ

คู่มือพยาบาลวิชาชีพ
===================

ยืนยันผลคัดกรอง มอบหมายผู้ดูแลผู้ป่วยสีเหลือง ติดตามสัญญาณชีพ และดำเนินการสัญญาณเตือนตามลำดับ

เมนูหลักที่ใช้  คัดกรอง ติดตาม และ ผู้ป่วยของฉัน

ทบทวนผลก่อนยืนยันสี
===================

1. เปิด ‘คัดกรอง’ เลือก ‘ดูข้อมูลผู้ป่วยและสัญญาณชีพ’ ตรวจ HN อาการ ค่าที่วัด ผล AI และเหตุผล/flags ของระบบให้ครบ
2. กด ‘ยืนยันตามคำแนะนำ’ เมื่อเห็นด้วย หรือเลือกสีแดง ชมพู เหลือง เขียว หรือขาวตามผลประเมินของพยาบาล หากเปลี่ยนจากคำแนะนำต้องระบุเหตุผลเพิ่มเติม
3. ถ้าข้อมูลต้นทางยังไม่พร้อม เลือก ‘กลับไปประเมินข้อมูลสุขภาพใหม่’ เพื่อให้จุดวัดค่าแก้ข้อมูล ผล AI เป็นข้อมูลสนับสนุนและยังไม่ใช่ผลยืนยันของพยาบาล

สีที่ยืนยันส่งผู้ป่วยไปไหน
==========================

1. สีแดงและสีชมพูถูกส่งเข้ารายการฉุกเฉิน ส่วนสีเขียวและสีขาวเข้าสู่คิว OPD ตามระดับและเวลารอ ตรวจข้อความผลลัพธ์หลังยืนยัน
2. เมื่อเลือกสีเหลือง ระบบเปิด ‘มอบหมายผู้ดูแลและอุปกรณ์เฝ้าระวัง’ เลือกพยาบาลที่ขึ้นเวรและรับผู้ป่วยได้ พร้อมอุปกรณ์ที่ว่าง แล้วกด ‘ยืนยันพยาบาล + อุปกรณ์ + สีเหลือง’
3. หากไม่มีพยาบาลหรืออุปกรณ์ที่เลือกได้ ให้ประสานผู้ดูแลตรวจเวรและการจับคู่ ผู้ป่วยสีเหลืองยังรอเรียกตรวจ OPD พร้อมการเฝ้าระวัง ไม่ได้หมายถึงเปิดการนอนโรงพยาบาล

เฝ้าระวังและระบุตัวผู้ป่วยด้วยอุปกรณ์
=====================================

1. เปิด ‘ติดตาม’ ตรวจชื่อ/HN อุปกรณ์ พยาบาลผู้รับผิดชอบ สัญญาณชีพล่าสุด และเวลาที่รับข้อมูล กดเปิดรายละเอียดเมื่ออยากดูประวัติค่าและผลตรวจ
2. ปุ่ม ‘ส่งเสียงระบุตัวผู้ป่วย’ ส่งคำสั่งไปอุปกรณ์ที่จับคู่และออนไลน์ ตรวจผล ‘รออุปกรณ์’ ‘รอผล’ หรือ ‘ส่งเสียงแล้ว’ การกดปุ่มอย่างเดียวไม่ได้ยืนยันว่าเสียงดังแล้ว
3. ถ้าขึ้นออฟไลน์หรือยังไม่ได้จับคู่ ให้ตรวจการเชื่อมต่อและประสานเจ้าหน้าที่เครื่องมือแพทย์ ค่าล่าสุดต้องอ่านพร้อมเวลารับข้อมูล ไม่ใช่ถือว่าค่าเก่าเป็นค่าปัจจุบัน

คู่มือพยาบาลวิชาชีพ ต่อ
=======================

รับทราบและจัดการสัญญาณเตือน
===========================

1. กด ‘แจ้งเตือนการเฝ้าระวัง’ ตรวจผู้ป่วยและข้อความ แล้วกด ‘รับทราบและไปตรวจผู้ป่วย’ จากนั้นกด ‘เริ่มตรวจผู้ป่วย’ เมื่อเริ่มดำเนินการจริง การปิดป๊อปอัปอย่างเดียวไม่ปิด Alert
2. ในสถานะกำลังตรวจ เลือก ‘False alarm’ ‘กลับไปเฝ้าระวัง’ หรือ ‘แจ้งแพทย์ / ยกระดับ’ ตามผลที่ตรวจแล้ว หากยกระดับ ให้ปิดด้วย ‘ปิดหลังจัดการ / เฝ้าระวังต่อ’ เมื่อจัดการเสร็จ
3. กรณีต้องส่ง ER ให้เปิดรายละเอียดผู้ป่วย กรอกเหตุผล และกด ‘ส่งต่อ ER’ หลังรับทราบและเริ่มตรวจแล้ว ระบบจะยุติการจับคู่และนำเคสออกจากการติดตาม

ตรวจผู้ป่วยที่รับผิดชอบและสิ้นสุดการติดตาม
==========================================

1. เมนู ‘ผู้ป่วยของฉัน’ แสดงเคสที่มอบหมายให้บัญชีนี้ ตรวจผู้รับผิดชอบก่อนส่งต่อเวร และประสานผู้ดูแลเปลี่ยนผู้รับผิดชอบเมื่อจบเวร การแจ้งเตือนสุขภาพแสดงแก่ผู้ที่เกี่ยวข้องตามสิทธิ์และการมอบหมาย
2. ในรายละเอียดการติดตาม ถ้ามีปุ่ม ‘เสร็จสิ้นการรักษา’ ให้ใช้เมื่อดำเนินการตามแผนเสร็จและสถานะอนุญาต ไม่ใช่กดจบเพียงเพราะรอตรวจเสร็จ การจ่ายยา รับเงิน และยืนยันออกจากโรงพยาบาลมีเจ้าหน้าที่แต่ละจุดดำเนินการต่อ

คู่มือเจ้าหน้าที่จัดคิว
=======================

เรียกคิว OPD กำหนดห้องตรวจ ปรับคิวอย่างมีเหตุผล และปิด Visit เมื่อผู้ป่วยรับบริการครบและออกจริง

เมนูหลักที่ใช้  คิว และ ปิด Visit

ดูรายการคิวและจอคิวกลาง
=======================

1. เปิด ‘คิว’ ตรวจเลขคิว ระดับเร่งด่วน เวลารอ และสถานะ ค้นหาชื่อ HN เลขบัตร หรือเบอร์โทรเพื่อหาเคส ลำดับ OPD คำนึงถึงระดับเร่งด่วนและเวลารอ
2. กด ‘เปิดจอแสดงคิวผู้ป่วย’ สำหรับจอสาธารณะ ซึ่งแสดงหมายเลขคิวและสถานะ ไม่มีข้อมูลส่วนบุคคล จอห้องยาและจอการเงินแยกจากจอ OPD
3. ‘รอเรียก’ คือยังไม่ส่งห้องตรวจ ‘เฝ้าระวังระหว่างรอ’ คือยังอยู่ในคิว OPD แต่มีอุปกรณ์ติดตาม และ ‘เรียกแล้ว’ จะแสดงห้องตรวจที่เลือก

เรียกคิวและเลือกห้องตรวจ
========================

1. เลือกรายการแล้วกด ‘เรียกคิว’ ระบบเปิดหน้า ‘เลือกห้องตรวจ’ ตรวจชื่อ/Visit แล้วเลือกหมายเลขห้องที่ต้องการส่งผู้ป่วยไป
2. ตรวจว่ารายการเป็น ‘เรียกแล้ว’ พร้อมห้องที่ถูกต้อง และตรวจจอคิว ผู้ป่วยจะปรากฏในรายการห้องตรวจของแพทย์หลังดำเนินการสำเร็จ
3. หากต้องเรียกข้ามลำดับ ระบบอาจขอเหตุผล ให้ระบุสาเหตุที่เกิดขึ้นจริงเพื่อเก็บประวัติ ห้ามใช้การปรับคิวแทนการประเมินระดับโดยพยาบาล

ปรับคิว ย้ายห้อง หรือยกเลิก
===========================

1. กด ‘จัดลำดับคิว’ เลือกรูปแบบ/เลขคิวที่ต้องการ กรอกเหตุผลแล้วกด ‘บันทึกและสร้าง Log’ ตรวจเลขคิวใหม่ก่อนเรียกต่อ
2. ผู้ป่วยที่เรียกแล้วใช้ ‘ย้ายผู้ป่วย’ เลือกห้องปลายทางหรือส่งกลับไปรอเรียก กรอกหมายเหตุแล้วกด ‘ยืนยันการย้าย’ เมื่อกลับไปรอให้เรียกอีกครั้งจากรายการคิว
3. ใช้ ‘ยกเลิกคิว’ เฉพาะรายที่ควรยกเลิกและระบบเปิดให้ทำ อ่านกล่องยืนยันก่อนกด ประวัติการรับบริการจะยังถูกเก็บไว้

ปิด Visit หลังรับบริการครบ
==========================

1. เปิดเมนู ‘ปิด Visit’ ตรวจชื่อ/HN และสถานะยา/การเงิน ถ้าแสดง ‘รอขั้นตอนก่อนหน้า’ ต้องให้จุดบริการนั้นดำเนินการก่อน
2. เมื่อแสดง ‘พร้อมปิด Visit’ และผู้ป่วยออกจากโรงพยาบาลจริงแล้ว กด ‘ยืนยันออก · ปิด Visit’ ระบบบันทึกผู้ยืนยันและเวลา
3. การเงินต้องเสร็จ และห้องยาต้องจ่ายแล้วหรือมีการยืนยันเส้นทางไม่มียา จึงปิดได้ การปิด Visit ช่วยให้ผู้ป่วยกลับมารับบริการครั้งใหม่ได้โดยไม่มีงานครั้งเก่าค้าง

คู่มือแพทย์
===========

ตรวจผู้ป่วยตามห้อง บันทึกผลตรวจ และส่งต่อแผนยา/การเงินพร้อมเอกสารที่เกี่ยวข้อง

เมนูหลักที่ใช้  ห้องตรวจ

เลือกห้องและเริ่มประเมิน
========================

1. เปิด ‘ห้องตรวจ’ เลือกห้องที่ทำงาน จะเห็นรายชื่อผู้ป่วยที่ถูกเรียกเข้าห้องนั้น ใช้ ‘เปลี่ยนห้องที่กำลังดู’ หากต้องดูห้องอื่น
2. ตรวจผู้ป่วยแล้วกด ‘ดูข้อมูล’ เพื่อทบทวนทะเบียน สัญญาณชีพ และผลคัดกรอง หรือกด ‘ประเมินโดยแพทย์’ เลือกชื่อแพทย์ผู้ตรวจแล้วกด ‘ยืนยันและเข้าประเมิน’
3. หากต้องย้ายผู้ป่วย กด ‘ย้ายผู้ป่วย’ เลือกห้องปลายทางหรือกลับไปรอเรียก ระบุเหตุผล และกด ‘ยืนยันการย้าย’

บันทึกผลตรวจและแผนการรักษา
==========================

1. ทบทวนข้อมูลที่ระบบกรอกให้จากทะเบียน/คัดกรองก่อนบันทึก กรอกผลประเมิน วินิจฉัย และแผนการรักษาตามการตรวจจริง ข้อมูลเสริมและผลตรวจเพิ่มเติมใส่เมื่อมีข้อมูล
2. หากมีแผนเฝ้าระวังหลังตรวจหรือนัดครั้งต่อไป เลือกตัวเลือกที่เกี่ยวข้องและกรอกรายละเอียด จากนั้นกด ‘บันทึกผลตรวจและไปขั้นตอนยา →’
3. การบันทึกผลตรวจส่งเข้าสู่หน้า ‘สรุปและส่งต่อหลังตรวจ’ ยังต้องเลือกเส้นทางมียาหรือไม่มียา จึงจะส่งงานให้ห้องยา/การเงินครบ

สั่งยาและส่งใบสั่งยา
====================

1. ในหน้าแผนหลังตรวจ พิมพ์ชื่อไทย/อังกฤษหรือคำค้นใน ‘ค้นหาและเลือกชื่อยา / เวชภัณฑ์’ แล้วเลือกจากรายการ มีทั้งยารับประทานและยาทา ตรวจข้อมูลที่เติมให้ก่อนใช้
2. กรอกความแรง จำนวน ขนาด/วิธีใช้ ความถี่ ระยะเวลา หน่วยนับ ราคา และคำแนะนำตามรายการที่ต้องสั่ง กด ‘+ บันทึกรายการนี้’ ทีละรายการ แล้วตรวจทานตารางยา
3. เมื่อรายการครบ กด ‘ยืนยันและส่งใบสั่งยาไปห้องยา →’ ระบบเข้าคิวห้องยาและการเงิน หลังส่งแล้วรายการถูกล็อก ไม่สามารถลบรายการจากหน้านี้ได้

ไม่มียา เอกสาร และทบทวนงานหลังตรวจ
==================================

1. ถ้าไม่มีรายการยากลับบ้าน ใช้ ‘ยืนยัน “ไม่มียา” และส่งต่อ’ ระบบข้ามห้องยาและส่งให้การเงินตรวจสิทธิ/ค่าใช้จ่าย ถ้ามีรายการยาแล้วต้องตรวจทานเส้นทางก่อนส่ง
2. ถ้าผู้ป่วยร้องขอ เปิดส่วน ‘ใบรับรองแพทย์’ กรอกความเห็นและวันพัก กด ‘สร้างใบรับรอง’ หรือ ‘อัปเดตใบรับรอง’ แล้ว ‘เปิดเอกสาร’ เพื่อตรวจและพิมพ์
3. ในรายการห้องตรวจส่วน ‘งานหลังตรวจวันนี้’ กด ‘เปิดแผนหลังตรวจ’ เพื่อตรวจความคืบหน้า ยาและการเงินต้องครบ ก่อนเจ้าหน้าที่จัดคิวปิด Visit เมื่อผู้ป่วยออกจริง

คู่มือเจ้าหน้าที่ฉุกเฉิน
========================

รับช่วงผู้ป่วยฉุกเฉินจากคัดกรองหรือการเฝ้าระวัง และบันทึกผลจำหน่ายหรือส่งต่อหลังดูแล

เมนูหลักที่ใช้  ฉุกเฉิน

ตรวจผู้ป่วยที่ส่งเข้าฉุกเฉิน
============================

1. เปิดเมนู ‘ฉุกเฉิน’ ตรวจรายการ ‘ผู้ป่วยฉุกเฉิน’ ซึ่งรวมเคสสีแดง/ชมพูที่ยืนยันแล้วและเคสที่ส่ง ER จากการเฝ้าระวัง
2. ตรวจชื่อ HN เลข Visit ระดับคัดกรอง เวลายืนยัน และเหตุผลส่งต่อ กด ‘ดูประวัติผู้ป่วย’ เพื่อทบทวนข้อมูลที่เกี่ยวข้องก่อนรับช่วง

รับเคสเพื่อเริ่มดูแล
====================

1. เมื่อรับช่วงรายนั้นแล้ว กด ‘รับเคส’ ตรวจว่ามีข้อมูลรับเคสและชื่อผู้รับช่วงปรากฏ เพื่อให้ทราบว่าใครกำลังรับผิดชอบ
2. เคสที่ยังไม่รับจะยังไม่เปิดคำสั่งปิดการดูแล/ส่งต่อ ถ้ารายการเปลี่ยนระหว่างทำงาน ให้รีเฟรชและตรวจสถานะก่อนดำเนินการซ้ำ

รักษาเสร็จและจำหน่าย
====================

1. หลังรับเคส เปิด ‘ปิดการดูแลฉุกเฉิน / ส่งต่อผู้ป่วย’ ใส่ผลการรักษาหรือหมายเหตุที่ต้องบันทึก
2. เมื่อการดูแลเสร็จและมีผลจำหน่ายแล้ว กด ‘รักษาเสร็จ / จำหน่าย’ อ่านและยืนยันกล่องคำถาม ระบบบันทึกผลและผู้ดำเนินการ

ส่งต่อหน่วยอื่นและตรวจประวัติ
=============================

1. หากต้องส่งต่อหน่วยงานภายนอก กรอกปลายทางและเหตุผลในส่วนส่งต่อ แล้วกด ‘ส่งต่อหน่วยอื่น’ ยืนยันเมื่อดำเนินการตามกระบวนการส่งต่อจริง
2. ตรวจผลในประวัติผู้ป่วยและ Audit Log เพื่อดูต้นทางการส่ง ER ผู้รับเคส และผลสิ้นสุดเคส ระบบนี้รองรับ OPD และการรับช่วงฉุกเฉิน ไม่ได้เปิดเตียงหรือจัดการผู้ป่วยนอนโรงพยาบาล

คู่มือเจ้าหน้าที่เครื่องมือแพทย์
================================

ลงทะเบียนอุปกรณ์ จับคู่กับ Visit ตรวจสถานะการเชื่อมต่อ และจัดการอุปกรณ์ที่ไม่พร้อมใช้งาน

เมนูหลักที่ใช้  อุปกรณ์

ลงทะเบียนและเปิดใช้อุปกรณ์
==========================

1. เปิด ‘อุปกรณ์’ ในหน้า ‘จัดการอุปกรณ์ IoT’ ส่วน ‘สร้าง Device ใหม่’ ใส่ device_id ที่ตรงกับตัวอุปกรณ์ กรอก api_key ที่กำหนดไว้ หรือเว้นว่างให้ระบบสร้างให้ แล้วนำ key ไปตั้งค่าในอุปกรณ์
2. เลือก ‘เปิดใช้งานทันที’ ตามความพร้อม แล้วกด ‘สร้าง Device’ ตรวจอุปกรณ์ในตาราง ปุ่ม activate/deactivate ใช้เปิดหรือปิดการยอมรับข้อมูลจากอุปกรณ์
3. API key เป็นข้อมูลยืนยันตัวอุปกรณ์ ใช้ ‘copy API key’ เมื่อตั้งค่าอุปกรณ์ และเก็บให้ผู้เกี่ยวข้องเท่านั้น การตั้ง active เป็นการอนุญาตใช้งาน ไม่ได้ยืนยันว่าอุปกรณ์เชื่อมต่ออยู่

จับคู่อุปกรณ์กับผู้ป่วยครั้งที่มารับบริการ
==========================================

1. เปิด ‘จับคู่อุปกรณ์’ เลือกรายการผู้ป่วย/Visit ที่ถูกต้องและอุปกรณ์ที่พร้อม แล้วกด ‘บันทึกการจับคู่’ หรือใช้ส่วน ‘ผูก Device กับผู้ป่วย/Visit’ ในหน้าจัดการอุปกรณ์
2. ตรวจคู่ Device–Visit ในรายการล่าสุดก่อนนำไปให้ผู้ป่วย อุปกรณ์หนึ่งเครื่องไม่ควรมีการจับคู่ที่ใช้งานพร้อมกันหลายราย และการมาครั้งใหม่ต้องตรวจ Visit ใหม่ด้วย
3. การยืนยันสีเหลืองของพยาบาลสามารถสร้างคู่พร้อมมอบหมายผู้ดูแลได้ หากอุปกรณ์ถูกใช้แล้ว ระบบจะไม่เปิดให้จับคู่ซ้ำ ต้องตรวจการจับคู่เดิมก่อน

ตรวจอุปกรณ์ออฟไลน์และคำสั่งส่งเสียง
===================================

1. ตรวจเวลาที่อุปกรณ์ส่งข้อมูลล่าสุดและสถานะการจับคู่ เมื่อมีแจ้งเตือน ‘อุปกรณ์เฝ้าระวังออฟไลน์’ กด ‘ตรวจสอบอุปกรณ์’ แล้วตรวจไฟเลี้ยง เครือข่าย และค่าประจำเครื่อง
2. device_id และ api_key ในอุปกรณ์ต้องตรงกับรายการที่เปิดใช้งาน หาก active แต่ไม่มีข้อมูลใหม่ ให้ตรวจการส่งข้อมูลจริงและการตอบกลับจากระบบ
3. ปุ่มส่งเสียงบนหน้าติดตามเป็นงานของผู้เฝ้าระวัง หากรอคำสั่งนานหรือไม่ดัง ให้ช่วยตรวจว่าอุปกรณ์รับและตอบรับคำสั่งได้ รวมทั้งการต่อ buzzer ไม่ใช่อาศัยสถานะ active อย่างเดียว

ปลดคู่และจัดการเครื่องที่เลิกใช้งาน
===================================

1. ใช้ ‘unpair’ เมื่อควรยุติการจับคู่กับ Visit เดิม แล้วตรวจว่าผู้ป่วยรายนั้นไม่กำลังใช้อุปกรณ์อยู่ ก่อนนำไปจับคู่รายใหม่
2. เครื่องที่ยังไม่พร้อมใช้ให้ deactivate ส่วน delete ใช้เฉพาะเมื่อยืนยันว่าต้องลบรายการนั้น ตรวจ device_id และกล่องยืนยันก่อนดำเนินการ
3. หลังจัดการอุปกรณ์ให้ประสานพยาบาลตรวจค่าล่าสุดและผู้ป่วยที่จับคู่ การรับทราบหรือปิด Alert ด้านสุขภาพเป็นงานของพยาบาลผู้ดูแล

คู่มือเภสัชกร
=============

ตรวจใบสั่งยา จัดยา เรียกคิวรับยา และยืนยันจ่ายจริง พร้อมจัดการผู้ป่วยที่ไม่มาตามคิว

เมนูหลักที่ใช้  ห้องยา

เลือกใบสั่งยาที่ยังรอรับบริการ
==============================

1. เปิด ‘ห้องยา’ รายการคิวแสดงเฉพาะใบสั่งยาที่รอห้องยา กำลังจัด หรือพร้อมจ่าย ค้นหา HN ชื่อ หรือชื่อยา และใช้แท็บ ‘รอรับ’ ‘กำลังจัด’ ‘พร้อมจ่าย’ แยกงาน
2. คลิกแถวผู้ป่วยเพื่อดูข้อมูลและใบสั่งยา ตรวจชื่อ/HN ประวัติแพ้ยา ความแรง ขนาด วิธีใช้ และจำนวน รายการจ่ายยาแล้วจะไม่อยู่ในคิวรอรับยา
3. สถานะ ‘กำลังเรียก’ หรือ ‘ไม่มา’ เป็นสถานะของการเรียกคิว ส่วน ‘กำลังจัดยา’/‘พร้อมจ่ายยา’ เป็นสถานะใบสั่งยา ต้องตรวจทั้งสองส่วน

บันทึกการจัดยาตามขั้นตอน
========================

1. เมื่อรับใบสั่งยาไปจัด กด ‘เริ่มจัดยา’ สถานะเปลี่ยนจากรอห้องยาเป็นกำลังจัดยา ตรวจรายการยาทุกรายการของคนที่เลือก
2. เมื่อจัดและตรวจครบแล้ว กด ‘ยาพร้อมจ่าย’ รายการเป็นพร้อมจ่ายยา การกดเปลี่ยนสถานะเป็นการบันทึกผลการทำงานจริง ไม่ได้หมายถึงระบบจัดยาหรือจ่ายยาอัตโนมัติ
3. ส่วน ‘ตัวเลือกสถานะเพิ่มเติม’ ใช้แก้สถานะที่จำเป็น เช่น ยกเลิกใบสั่งยา ต้องตรวจผลกระทบและกล่องยืนยันก่อนบันทึก

เรียกคิวและจัดการคนไม่มา
========================

1. ส่วน ‘จัดการคิว’ เปิดปุ่ม ‘เรียกคิว’ ให้รายแรกตามเวลาที่เข้าห้องยา ใช้เลขคิวเดิมของผู้ป่วยและลำดับห้องยาแยกกัน หากมีรายกำลังเรียกอยู่ ให้ดำเนินการรายนั้นก่อน
2. เมื่อเรียกแล้วผู้ป่วยไม่มา ให้กด ‘ไม่มา · ข้ามคิว’ และยืนยัน รายนี้เก็บสถานะไม่มาไว้เพื่อให้เรียกรายถัดไปได้ เมื่อผู้ป่วยกลับมา ใช้ ‘กลับเข้าคิวท้ายแถว’
3. กด ‘เปิดจอคิวห้องยา’ สำหรับจอสาธารณะ จอนี้แสดงคิวห้องยาแยกจาก OPD/การเงินและไม่แสดงชื่อหรือ HN ผู้ป่วย

ยืนยันจ่ายยาและตรวจงานที่เสร็จ
==============================

1. เมื่อส่งมอบยาให้ผู้ป่วยจริงแล้ว ตรวจชื่อ/HN และรายการอีกครั้ง ก่อนกด ‘ยืนยันจ่ายยาแล้ว’ ระบบบันทึกเภสัชกรและเวลาจ่ายพร้อมนำออกจากคิวรอรับยา
2. ตรวจข้อความสำเร็จและตัวเลข ‘จ่ายแล้ววันนี้’ ถ้าต้องดูประวัติของคนที่เสร็จแล้ว ให้ค้นหาในเมนู ‘ผู้ป่วย’ และเปิด Visit ที่เกี่ยวข้อง
3. การจ่ายยาเสร็จเป็นหนึ่งในขั้นตอนหลังตรวจ ผู้ป่วยยังต้องดำเนินการการเงินให้ครบ และเจ้าหน้าที่จัดคิวยืนยันออกจากโรงพยาบาลเพื่อปิด Visit

คู่มือเจ้าหน้าที่การเงิน
========================

ตรวจค่าใช้จ่ายและสิทธิ เรียกคิวรับชำระ ออกใบเสร็จ และตรวจยอดค้างหรือยอดที่รวมจาก Visit เก่า

เมนูหลักที่ใช้  การเงิน

เลือกงานและเข้าใจสถานะบิล
=========================

1. เปิด ‘การเงิน’ ค่าเริ่มต้น ‘รอรับบริการ’ แสดงงานที่ยังไม่เสร็จ ค้นหา HN ชื่อ หรือเลข Visit แล้วคลิกผู้ป่วยเพื่อดูรายการชำระ
2. ‘รอตรวจยอด’ คือบิลยังรอสรุป ‘รอชำระ’ คือมียอดผู้ป่วยต้องจ่าย ‘เสร็จแล้ว’ รวมรายการชำระแล้วหรือปิดยอดศูนย์ ส่วน ‘ค้างยอด’ ใช้ตรวจภาระที่ยังไม่ชำระ
3. ตรวจชื่อ/HN และ Visit ให้ตรงก่อนทำรายการ คนเดิมอาจมีหลาย Visit และยอดรวมจากบิลเก่าแสดงเป็นรายการแยก

เรียกคิวและจัดการผู้ป่วยที่ไม่มา
================================

1. ส่วน ‘จัดการคิวการเงิน’ ใช้ ‘เรียกคิว’ ตามเวลาที่เข้าคิวการเงิน เลขคิวผู้ป่วยคงเดิม แต่ลำดับของจุดการเงินแยกจาก OPD และห้องยา
2. ผู้ป่วยที่เรียกแล้วไม่มา ใช้ ‘ไม่มา · ข้ามคิว’ เพื่อให้ดำเนินการรายถัดไปได้ เมื่อกลับมา ใช้ ‘กลับเข้าคิวท้ายแถว’ โดยยังเก็บบิลเดิมไว้
3. เปิดจอคิวการเงินสำหรับจอสาธารณะ จอแสดงเฉพาะหมายเลขคิวและสถานะ ไม่มีข้อมูลผู้ป่วยหรือยอดชำระส่วนบุคคล

ตรวจสิทธิและคำนวณยอด
====================

1. เปิดรายการตรวจยอด/รับชำระ เลือกประเภทสิทธิ กรอกเลขสิทธิหรือกรมธรรม์ เปอร์เซ็นต์ครอบคลุม หมายเหตุ และค่าใช้จ่ายอื่นตามข้อมูลที่ตรวจสอบแล้ว
2. กด ‘บันทึกสิทธิและคำนวณยอดใหม่’ จากนั้นตรวจค่าตรวจแพทย์ ค่ายา ค่าใช้จ่ายอื่น ส่วนสิทธิครอบคลุม และ ‘ยอดที่ผู้ป่วยต้องชำระ’ ก่อนแจ้งผู้ป่วย
3. ระบบเติมเปอร์เซ็นต์เริ่มต้นเมื่อเลือกประเภทสิทธิ ต้องตรวจว่าใช้ได้กับรายนี้ ยอดค้างเดิมที่ย้ายมาแสดงแยกจากค่าใช้จ่าย Visit ปัจจุบันและไม่ใช้สิทธิใหม่ลดซ้ำ

คู่มือเจ้าหน้าที่การเงิน ต่อ
============================

รับชำระหรือยืนยันยอดศูนย์และออกใบเสร็จ
======================================

1. เมื่อตรวจยอดและรับชำระจริงแล้ว กด ‘ยืนยันรับชำระ … บาท’ พร้อมยืนยันกล่องคำถาม หากยอดเป็น 0 บาท ให้กด ‘ยืนยันปิดยอดและออกใบเสร็จ’ เพื่อบันทึกว่าไม่มีค่าใช้จ่ายผู้ป่วย
2. ระบบบันทึกผู้รับชำระ เวลา และเปิดใบเสร็จ ตรวจข้อมูลและยอดก่อนพิมพ์ รายการที่เสร็จแล้วเปิดเอกสารได้จากแท็บ ‘เสร็จแล้ว’ หรือปุ่ม ‘เปิดใบเสร็จ’ ในรายละเอียด
3. เมื่อการเงินเสร็จแล้ว ผู้ป่วยยังต้องรับยาหากมีใบสั่งยา และเจ้าหน้าที่จัดคิวเป็นผู้ยืนยันออก/ปิด Visit เมื่อรับบริการครบและออกจริง

ตรวจยอดค้างและบิลที่โอนยอด
==========================

1. ใช้แท็บ ‘ค้างยอด’ ตรวจรายการที่ยังไม่ได้ชำระ ดู Visit และยอดก่อนติดตามผู้ป่วย สถานะไม่มาตามคิวไม่ได้หมายถึงยกเลิกบิลหรือยกหนี้
2. ถ้าเวชระเบียนเปิด Visit ใหม่กรณีเร่งด่วนพร้อมรวมบิล บิลเก่าจะอยู่ ‘โอนยอดแล้ว’ ดูข้อมูลบิลปลายทางและรับชำระจากบิลใหม่นั้น
3. บิลที่โอนยอดไม่เปิดให้รับเงินจากต้นทางซ้ำ ตรวจยอดค้างเดิมในรายละเอียดบิลใหม่และประวัติผู้ป่วยก่อนปิดยอด

คู่มือผู้ดูแลระบบสูงสุด
=======================

ดูภาพรวม จัดบทบาทและเวร มอบหมายผู้ดูแล ตรวจประวัติ และใช้เครื่องมือรายงาน/ทดสอบระบบตามงานที่ต้องทำ

เมนูหลักที่ใช้  ภาพรวม บุคลากร เวร Admin และ รายงาน

ดูภาพรวมและตรวจขั้นตอนผู้ป่วย
=============================

1. เปิด ‘ภาพรวม’ เพื่อดูงานในระบบ จากนั้นใช้ ‘ผู้ป่วย’ ตรวจ Visit ล่าสุด แท็บสถานะ และยอดค้าง เปิดประวัติรายคนเพื่อดูว่าใครดำเนินการและค้างจุดไหน
2. โฟลว OPD คือ ลงทะเบียน → วัดค่า → พยาบาลยืนยัน → คิว/ห้องตรวจ → แผนยาและการเงิน → ยืนยันออก/ปิด Visit ส่วนสีแดง/ชมพูหรือส่ง ER จะเป็นงานรับช่วงฉุกเฉิน
3. หากสถานะไม่เดินต่อ ให้เปิดหน้าของจุดบริการที่ค้างและตรวจข้อความผิดพลาดก่อนเปลี่ยนข้อมูล การตรวจเสร็จเพียงอย่างเดียวยังไม่ทำให้ยา/การเงิน/ปิด Visit เสร็จตาม

จัดบุคลากร บทบาท และเวร
=======================

1. เปิด ‘บุคลากร’ แท็บ ‘รายชื่อบุคลากร’ เพื่อค้นหาบัญชี แก้ชื่อ/รูป เปลี่ยนประเภท และตรวจสถานะขึ้นเวร/พร้อมรับผู้ป่วย ตรวจ username ก่อนเปลี่ยนหน้าที่ของใคร
2. เปิด ‘เวร’ เลือกวันที่แล้วกด ‘ดูวันที่’ ใช้ ‘เพิ่มเวรในวันที่เลือก’ กรอกบุคลากร วัน เวลาเริ่ม/สิ้นสุด สถานะ และหมายเหตุ แล้วกด ‘+ บันทึกเวร’ แก้ไขหรือลบจากรายการวันนั้น
3. ‘ระงับบัญชี (ไม่ลบข้อมูล)’ ใช้พักการเข้าใช้งานของบัญชีนั้น และ ‘เปิดใช้งานบัญชี’ ใช้คืนการใช้งาน ตรวจเหตุผลก่อนกด สถานะเวรกับสถานะบัญชีเป็นคนละเรื่อง

มอบหมายผู้ดูแลและส่งต่อเวร
==========================

1. ใน ‘บุคลากร’ แท็บ ‘ผู้ป่วยและผู้รับผิดชอบ’ ตรวจพยาบาลที่ขึ้นเวร พร้อมรับผู้ป่วย และภาระปัจจุบัน เลือกผู้ดูแลแล้วกด ‘มอบหมาย’ หรือ ‘เปลี่ยนผู้ดูแล’
2. ใช้ ‘เลือกคนว่างให้อัตโนมัติ’ สำหรับรายที่เลือก หรือ ‘มอบหมายเคสที่ว่างอัตโนมัติ’ สำหรับเคสว่างหลายราย ตรวจผลที่ระบบเลือกและข้อจำกัดรับผู้ป่วยหลังดำเนินการ
3. ในแท็บ ‘ส่งต่อเวร’ เลือกผู้ส่ง/ผู้รับตามหน้าจอแล้วกด ‘ส่งต่อทั้งหมด’ เมื่อมีการส่งต่อจริง ตรวจผู้ป่วยและผู้รับผิดชอบใหม่เพื่อให้ Alert ถึงผู้ดูแลที่ถูกคน

คู่มือผู้ดูแลระบบสูงสุด ต่อ
===========================

ทดสอบสิทธิ์และดูข้อมูลระบบ
==========================

1. ส่วน ‘ทดสอบสิทธิ์บทบาท’ ในแถบเมนู เลือกหน้าที่ ระบบสลับเมนู/สิทธิ์ของบทบาทนั้นชั่วคราว หากต้องกลับมาทำงานผู้ดูแล ให้เลือกผู้ดูแลระบบสูงสุดกลับก่อน
2. เปิด ‘Admin’ สำหรับเครื่องมือทดสอบและตรวจระบบ เครื่องมือสร้างสถานการณ์หรือส่งข้อมูลเซนเซอร์เป็นข้อมูลทดสอบ ควรตรวจรายการที่เลือกก่อนรันหรือลบสถานการณ์
3. หน้าจัดการฐานข้อมูลและ Django Admin ใช้ตรวจตาราง/ระเบียนตามสิทธิ์ ตารางระบบบางส่วนเปิดดูได้อย่างเดียว การแก้ข้อมูลโดยตรงต้องตรวจว่าไม่ข้ามกฎและประวัติของงานบนหน้าเว็บ

รายงานและการประเมิน AI
======================

1. เปิด ‘รายงาน’ เพื่อดูสรุปเวลารอ คอขวดของกระบวนการ และแนวโน้ม 6 เดือนล่าสุด ใช้ตัวเลือกส่งออก CSV/Excel/PDF เมื่อต้องนำผลไปใช้งาน ตรวจจำนวน Visit และรายละเอียดราย Visit ที่ใช้คำนวณ
2. เปิด ‘AI’ เพื่อดูผลประเมินและการเรียนรู้ที่ระบบแสดง แยกผลของโมเดลออกจากระดับสุดท้ายที่พยาบาลยืนยัน ค่าประเมินโมเดลไม่ได้หมายถึงแพทย์วินิจฉัยแล้ว
3. เมื่อติดตามปัญหาให้ใช้ประวัติ Visit และ Audit Log ประกอบ รายงานหรือหน้าที่มีข้อมูลส่วนบุคคลควรเปิดให้เฉพาะผู้เกี่ยวข้อง

กรณีใช้งานและปัญหาที่พบบ่อย
===========================

1. คู่มือไม่เด้ง: อาจเคยเปิดแล้วในแท็บ/การเข้าสู่ระบบเดิม หรือเลือกไม่แสดงวันนี้ไว้ ให้เปิดจากเมนูคู่มือการใช้งาน ถ้ายังไม่เห็นฟีเจอร์ ให้ตรวจว่ารุ่นใหม่ถูก deploy และ static files ถูกเผยแพร่แล้ว
2. เปลี่ยนบัญชีแล้วต้องได้คู่มือของบัญชีใหม่: ออกจากระบบก่อนเข้าบัญชีอื่น คู่มือและตัวเลือกซ่อนวันนี้แยกตามบัญชีและบทบาทในเบราว์เซอร์นั้น
3. เปลี่ยนเครื่อง เบราว์เซอร์ หรือใช้โหมดส่วนตัว: การจำตัวเลือกอาจไม่ตามไป หรือถูกล้างเมื่อปิดโหมดส่วนตัว การเลือกซ่อนวันนี้ไม่ได้เก็บในฐานข้อมูลส่วนกลาง
4. เบราว์เซอร์แจ้งว่าจำการตั้งค่าไม่ได้: ยังอ่าน ข้าม และเปิดคู่มือได้ แต่คู่มืออาจเด้งอีกเมื่อเปิดหน้าใหม่ ตรวจการอนุญาต localStorage/sessionStorage ของเบราว์เซอร์
5. ไม่เห็นผู้ป่วยในหน้างาน: ตรวจแท็บสถานะ ช่วงงานของหน้าจอ และ Visit ที่เลือก คนที่เสร็จแล้วอาจถูกซ่อนจากคิวรอ แต่ยังมีประวัติอยู่
6. active แต่ buzzer ไม่ดัง: active เป็นการอนุญาตอุปกรณ์ใช้งาน ไม่ยืนยันออนไลน์หรือส่งเสียงแล้ว ต้องตรวจเวลารับข้อมูล การจับคู่ การรับ/ตอบคำสั่ง และตัวอุปกรณ์
7. ผู้ป่วยไม่มาตามคิวห้องยา/การเงิน: ใช้ไม่มาและข้ามคิว จากนั้นกลับเข้าคิวท้ายแถวเมื่อกลับมา สถานะไม่มาไม่ใช่การยกเลิกบิลหรือยกหนี้

ผลการตรวจสอบฟีเจอร์คู่มือ
=========================

วันที่ 7 ตุลาคม 2569 รันทดสอบอัตโนมัติฝั่ง Django 24 รายการ และ JavaScript DOM 9 รายการ ผ่านทั้งหมด 33 รายการ ผลชุดนี้ตรวจฟีเจอร์คู่มือและสิทธิ์ที่เกี่ยวข้อง ไม่ใช่ผลทดสอบทุกส่วนของระบบหรือค่าความแม่นยำของ AI

1. Django ตรวจว่าทุกบทบาทมีคู่มือ ลิงก์ตรงสิทธิ์ ผู้ไม่เข้าสู่ระบบไม่มีคู่มือ ตัวระบุเปลี่ยนเมื่อเข้าสู่ระบบ และผู้ดูแลสวมบทบาทแล้วได้คู่มือที่ถูกต้อง
2. JavaScript ตรวจเปิดครั้งแรก ข้ามแล้วเปลี่ยนหน้า การซ่อนข้ามการเข้าสู่ระบบในวันเดิม การแสดงวันใหม่ การแยกบัญชี/บทบาท สารบัญ ปิดด้วย Escape ลิงก์หน้างาน และกรณี storage ถูกปิดกั้น
3. วันที่ 6 ตุลาคม 2569 ตรวจใน Chrome ด้วยฐานข้อมูลทดสอบแยก ครบ 9 ตำแหน่งและผู้ดูแล ตรวจหน้าเข้าใช้งาน การเปิดซ้ำ การซ่อนวันนี้ จอคอมและจอมือถือ โดยไม่พบ JavaScript page error
4. การตรวจ Django มีคำเตือนเดิมเรื่องตำแหน่ง cache แบบ relative ในสภาพแวดล้อมทดสอบ ไม่พบข้อผิดพลาดที่ทำให้ชุดทดสอบล้มเหลว

รายการสำหรับตรวจรับบนระบบใช้งานจริง
===================================

1. เข้าสู่ระบบด้วยบัญชีทดสอบของแต่ละตำแหน่ง และตรวจชื่อคู่มือกับเมนูที่เห็น
2. กดอ่าน เปลี่ยนหัวข้อ กดลิงก์หน้างาน แล้วเปิดคู่มือซ้ำจากแถบเมนู
3. กดข้ามแล้วเปลี่ยนหน้า ต้องไม่เด้งซ้ำในแท็บ/การเข้าสู่ระบบเดิม
4. ติ๊กไม่แสดงวันนี้ ออกจากระบบแล้วเข้าใหม่ ต้องไม่เด้ง แต่เมนูเปิดซ้ำต้องยังใช้ได้
5. ตรวจมือถือ และตรวจวันถัดไปตามเวลาไทยเมื่อเปิดหน้าใหม่

ควรทำรายการตรวจรับหลัง deploy ก่อนให้ผู้ใช้จริงเริ่มงาน และใช้บัญชี/ข้อมูลทดสอบที่อนุญาต

รายละเอียดสำหรับผู้ดูแลและผู้พัฒนา
==================================

ฟีเจอร์คู่มือไม่เพิ่มตารางหรือ migration และไม่เปลี่ยน API ผู้ป่วย โมเดล AI หรือกฎการรับชำระ การนำขึ้นระบบใช้ขั้นตอน deploy Django และเผยแพร่ static files ตามเดิม ไม่ต้อง build เว็บผู้ป่วย Next.js สำหรับการเปลี่ยนแปลงชุดนี้

ตำแหน่งไฟล์ที่เกี่ยวข้อง
========================

1. accounts/role_guides.py เก็บเนื้อหาตามบทบาท เป็นแหล่งเดียวกันสำหรับคู่มือในเว็บและรายงานฉบับนี้
2. accounts/guide_context.py และ accounts/context_processors.py เลือกคู่มือ แปลงลิงก์ และส่งข้อมูลบัญชี บทบาท วันตามเวลาไทย และตัวระบุการเข้าใช้งานไปหน้าเว็บ
3. accounts/apps.py กำหนดตัวระบุใหม่เมื่อเข้าสู่ระบบ ตัวระบุคู่มือไม่ใช่ session key ที่ใช้ยืนยันตัวตน
4. queues/templates/includes/main_nav.html และ staff_role_guide.html แสดงเมนูและโครงสร้างป๊อปอัป
5. static/css/staff-role-guide.css และ static/js/staff-role-guide.js กำหนดหน้าตา การอ่าน และการจำตัวเลือกในเบราว์เซอร์
6. accounts/test_role_guides.py และ scripts/test_staff_role_guide.mjs เป็นชุดทดสอบ ส่วน docs/staff-role-guides.md อธิบายการดูแลฟีเจอร์
7. scripts/build_staff_manual.cjs สร้างรายงาน PDF และ TXT จากเนื้อหาคู่มือ โดยไม่เชื่อมฐานข้อมูล

แหล่งตรวจสอบฟีเจอร์ที่มีอยู่ก่อน
================================

คิวห้องยา/การเงินและจอแยกอยู่ใน opd/workflow_views.py และ opd/templates/service_queue_display.html การตรวจสถานะผู้ป่วยและเริ่ม Visit ใหม่กรณีเร่งด่วนอยู่ใน patients/views.py การคำนวณและโอนยอดอยู่ใน opd/models.py สิทธิ์แต่ละบทบาทอยู่ใน accounts/access.py

ข้อควรปฏิบัติเมื่อปรับปรุงคู่มือ
================================

เมื่อเปลี่ยนชื่อปุ่มหรือ workflow ให้แก้เนื้อหาใน role_guides.py ตรวจลิงก์และสิทธิ์ รันทดสอบ และสร้างรายงานใหม่ ระบุวันและรุ่นที่ตรวจจริง ไม่ใช้คู่มือแทนการตรวจสถานะจากระบบหรือการตัดสินใจของเจ้าหน้าที่
