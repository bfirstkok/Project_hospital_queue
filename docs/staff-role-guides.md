# คู่มือการใช้งานในเว็บเจ้าหน้าที่

ป๊อปอัปมีเนื้อหาแยกสำหรับเวชระเบียน ผู้ช่วยพยาบาล พยาบาลวิชาชีพ
เจ้าหน้าที่จัดคิว แพทย์ เจ้าหน้าที่ฉุกเฉิน เจ้าหน้าที่เครื่องมือแพทย์
เภสัชกร เจ้าหน้าที่การเงิน และผู้ดูแลระบบสูงสุด

## พฤติกรรม

- หลังเข้าสู่ระบบ แสดงคำแนะนำของบทบาทที่ใช้งานจริง พร้อมปุ่ม **อ่านคู่มือ** และ **ข้าม**
- อ่านทีละหัวข้อได้ด้วยสารบัญหรือปุ่มก่อนหน้า/ถัดไป มีลิงก์เปิดหน้างานที่บทบาทนั้นเข้าถึงได้
- เมื่ออ่านหรือข้าม จะไม่เด้งซ้ำเมื่อเปลี่ยนหน้าในแท็บและการเข้าสู่ระบบครั้งเดิม
- **ไม่แสดงอีกในวันนี้** จำแยกบัญชีและบทบาทในเบราว์เซอร์นี้จนถึงวันถัดไปตามเวลา Asia/Bangkok
- เมนู **คู่มือการใช้งาน** เปิดอ่านได้เสมอ แม้เลือกไม่แสดงวันนี้ และเอาติ๊กออกเพื่อคืนการแสดงอัตโนมัติได้
- ผู้ดูแลที่สวมบทบาททดสอบจะได้รับคู่มือของบทบาทนั้น ไม่ใช่คู่มือผู้ดูแล
- หากเบราว์เซอร์ปิดกั้น storage ยังอ่านและข้ามได้ แต่ระบบจะแจ้งว่าจำตัวเลือกไม่ได้

## จุดที่แก้ไข

- `accounts/role_guides.py`: เนื้อหา หัวข้อ ขั้นตอน ชื่อปุ่ม และลิงก์ของทุกตำแหน่ง
- `accounts/guide_context.py`: เลือกคู่มือ แปลง route names และกำหนดบัญชี/บทบาท/วันที่/ตัวระบุการเข้าสู่ระบบ
- `accounts/apps.py`: สร้างตัวระบุใหม่เมื่อเข้าสู่ระบบ โดยไม่ใช้ session key จริงในหน้าเว็บ
- `accounts/context_processors.py`: ส่งคู่มือเข้า template ร่วม
- `queues/templates/includes/main_nav.html`: เมนูเปิดคู่มือและ include ป๊อปอัป
- `queues/templates/includes/staff_role_guide.html`: โครงสร้างหน้าต่างและส่วนอ่านคู่มือ
- `static/css/staff-role-guide.css`: หน้าตาและขนาดจอคอม/มือถือ
- `static/js/staff-role-guide.js`: เปิด/ปิด เปลี่ยนหัวข้อ และจำตัวเลือกด้วย localStorage/sessionStorage

ลิงก์ใช้ `url_name` ของ Django ไม่ hardcode URL; ถ้าต้องเปิดแท็บเฉพาะ
เพิ่ม `query` เช่น `{"view": "patients"}` ได้ คู่มือไม่เพิ่มสิทธิ์ให้บัญชี
และไม่เปลี่ยน workflow ผู้ป่วย

## ตรวจสอบก่อนปล่อยขึ้นระบบ

```sh
python manage.py test accounts.test_role_guides accounts.tests_access --settings=config.test_settings
node --check static/js/staff-role-guide.js
node --test scripts/test_staff_role_guide.mjs
git diff --check
```

ชุดทดสอบ Node ต้องมี `jsdom` ใน `patient-portal/node_modules` หรือกำหนด
`STAFF_GUIDE_TEST_NODE_MODULES` ไปยังโฟลเดอร์ dependencies ที่มีแพ็กเกจนี้
ไม่จำเป็นต้องติดตั้ง Node dependencies เพิ่มใน container เว็บ Django เพื่อใช้งานคู่มือ

ทดสอบในเบราว์เซอร์จริง: เข้าระบบแต่ละตำแหน่ง → อ่าน/ข้าม → เปลี่ยนหน้า →
เปิดจากเมนู → ติ๊กไม่แสดงวันนี้ → ออกจากระบบและเข้าใหม่ → ตรวจว่าไม่เด้ง →
เอาติ๊กออกแล้วเข้าใหม่ → ตรวจว่าเด้ง รวมทั้งหน้าจอมือถือ

ไม่มี migration หรือตารางใหม่ ใช้ขั้นตอน deploy Django และ collectstatic ตามปกติ
เพื่อให้ CSS/JavaScript ใหม่ถูกเผยแพร่ ไม่ต้อง build เว็บผู้ป่วย Next.js สำหรับฟีเจอร์นี้

## รายงานคู่มือสำหรับส่งต่อ

รายงานฉบับ PDF และข้อความ TXT อยู่ที่ `output/pdf/รายงานคู่มือการใช้งานระบบและฟีเจอร์ที่เพิ่ม`
ครอบคลุมทุกตำแหน่ง ฟีเจอร์คู่มือที่เพิ่มรอบนี้ ฟีเจอร์เดิมที่เกี่ยวข้อง ปัญหาที่พบบ่อย และผลทดสอบ
สร้างจากเนื้อหา `ROLE_GUIDES` เดียวกับหน้าเว็บเพื่อไม่ให้ขั้นตอนต่างกัน

สร้างรายงานใหม่ได้ด้วย `node scripts/build_staff_manual.cjs` โดยต้องมี Python,
Playwright และเบราว์เซอร์ หากใช้ชุดเครื่องมือแยก ให้กำหนด
`STAFF_GUIDE_ARTIFACT_PYTHON` และ `STAFF_GUIDE_ARTIFACT_NODE_MODULES` ตามตำแหน่ง runtime
ที่ใช้ ตรวจวันที่และข้อความผลทดสอบในสคริปต์ก่อนสร้างฉบับใหม่ และตรวจหน้ากระดาษ PDF ก่อนส่งต่อ
